# PromSafe V8 – улучшение существующего сайта

**Назначение:** обновлённая версия текущего Next.js-сайта PromSafe. Это не новый сайт и не замена архитектуры. Исправления внесены в исходники V7, соответствующие структуре опубликованного сайта на Railway.

## Что исправлено

### Дизайн и UX

- Более выразительный первый экран: логотип и блок экспертного позиционирования вместо пустой декоративной панели.
- Крупнее и читабельнее шрифты, лучше контраст, увеличены межстрочные интервалы и отступы.
- Страницы услуг сгруппированы по задачам; вместо однообразного каталога карточек – содержательный список услуг.
- База знаний получила редакционный формат: главный материал и отдельный список статей.
- Важные действия заметны, но без навязчивых призывов.
- Исправлены клавиатурные фокусы и ссылка «К основному содержимому».
- Улучшены мобильные размеры, структура сеток и поддержка reduced motion.
- Калькулятор теперь даёт рекомендацию по выбранной задаче, а не одинаковый результат для всех.

### Контент и доверие

- Убраны заметные внутренние выражения про разработку сайта и SEO.
- Убраны неподтверждённые заявления «24/7» из шапки, главной и контактов.
- На страницах услуг добавлены специализированные ситуации, возможные результаты и тематические ответы на вопросы.
- Убраны имена-инициалы с недоказанными годами аккредитации, пока заказчик не предоставит подтверждения.
- Предварительная оценка стоимости услуг сохраняется только после аудита. Перечень цен на документы оставлен по старому сайту, но требует подтверждения перед окончательной публикацией.

### SEO

- Уникальные метаданные для страниц услуг, отраслей и статей сохранены.
- Добавлены 2 полноценных информационных материала: «Охрана труда для малого бизнеса: с чего начать» и «Аутсорсинг или штатный специалист».
- Добавлены структурированные данные `Article` и `BreadcrumbList` для статей; `BreadcrumbList` для услуг.
- Создано изображение OpenGraph 1200×630 на базе официального логотипа.
- Расширена внутренняя перелинковка услуг и статей.
- Техническая карта сайта автоматически включает новые материалы.
- Обновлена версия Next.js до **15.5.26**, ранее успешно собравшаяся в Railway по данным владельца.

### Обращения и персональные данные

- Исправлена опасная логика формы: в тестовом режиме она больше не утверждает, что заявка получена компанией.
- До предоставления утверждённой политики обработки данных и рабочего CRM-подключения форма **по умолчанию отключена**. Вместо неё доступны работающие ссылки `tel:` и `mailto:`.
- Для включения формы требуются `NEXT_PUBLIC_LEAD_FORM_ENABLED=true`, `NEXT_PUBLIC_PRIVACY_POLICY_URL=...`, `EXTERNAL_WRITES_ENABLED=true`, `CRM_WEBHOOK_URL=...`; также нужна проверка доступности CRM и корректности согласия.

## Важное о тестовом домене и SEO

Текущая Railway-версия была получена и проверена с метаданными `noindex, nofollow`, а `canonical` и `sitemap` указывали на `https://promsafe.ru`. Это соответствует **тестовому развёртыванию**, но не означает, что на тестовом домене можно получать поисковый трафик.

**Не меняйте** `NEXT_PUBLIC_SITE_ENV=staging` на `production` до финального размещения на `promsafe.ru`, проверки доступности без VPN и настройки основного домена.

Для полноценного SEO на основном домене:

1. Получить подтверждение заказчика на публикацию страниц, текстов, цен, юридической информации.
2. Проверить `promsafe.ru` и все маршруты в РФ без VPN.
3. Настроить `NEXT_PUBLIC_SITE_ENV=production` и `NEXT_PUBLIC_SITE_URL=https://promsafe.ru` в финальной среде; собрать заново.
4. Проверить `robots.txt`, `sitemap.xml`, `canonical`, фактический статус 200 и отсутствие `noindex`.
5. Подтвердить домен в Яндекс Вебмастере, передать sitemap и подключить Метрику после настройки правовой части.
6. Поддерживать статьи и официальные источники в актуальном состоянии.

## Пошаговый запуск V8 на компьютере (Windows)

1. Распакуйте ZIP в новую папку, например `C:\PromSafe-V8`, не удаляя прежнюю V7.
2. Откройте **именно эту папку** в VS Code; `package.json` и `Dockerfile` должны находиться в её корне.
3. Откройте Terminal → New Terminal.
4. Выполните:

```powershell
npm install
npm list next
npm run typecheck
npm run build
npm run dev
```

5. Откройте `http://localhost:3000`. Проверьте главную, `/services`, `/services/outsourcing-ohrany-truda`, `/knowledge`, обе новые статьи, `/calculator`, `/contacts` и мобильную версию.
6. Проверьте `npm audit` и устраните действительно актуальные уязвимости **без** слепого `npm audit fix --force`.
7. Если все проверки успешны, решите, публиковать ли V8 на существующий сервис или создать отдельный staging-сервис. Существующую production-версию без финальной проверки не перезаписывайте.
8. Для существующего сервиса при необходимости выполните `railway link` и выберите нужный проект/service, проверьте выбранную среду, затем `railway up`. `Root Directory` должен быть пустым, поскольку исходники лежат в корне папки.

**При выкладке V8 на существующий Railway-домен** сайт останется в режиме staging/noindex, пока вы не поменяете переменные среды – и это правильно. Пример переменных приведён в `.env.example`.
