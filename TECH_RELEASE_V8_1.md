# PromSafe V8.1 – техническая доработка

Ветка изменений подготовлена поверх подтверждённой V8. Действующий Railway-сайт не заменён.

## Исправления

1. **Безопасность зависимостей:** Next.js 15.5.26 → **15.5.29**, React/React DOM 19.1.0 → **19.1.10** по официальным исправлениям безопасности от октября/ноября 2026 года.
2. Защита индексации: ни `NEXT_PUBLIC_SITE_ENV=production`, ни Railway-домен сами по себе не открывают сайт роботам. Для открытия нужны одновременно основной HTTPS-домен, `SITE_INDEXING_APPROVED=true` и production-режим.
3. 301-редирект с исторического `/socialaudit` на `/services/social-audit`, чтобы после переноса основного домена сохранить переходы по прежней ссылке. Остальные старые URL нуждаются в отдельной инвентаризации.
4. Улучшения мобильной навигации и доступности: Escape закрывает меню, `aria-current` для текущих пунктов, скрытие декоративных линий меню от чтения.
5. Разные объяснения блоков работ вместо одной повторяющейся фразы на каждой странице услуги.
6. API заявок: ограничение размера тела по реальным байтам, проверка JSON и телефона, проверка Origin при наличии, обработка ошибок Bitrix24 внутри HTTP 200, таймаут CRM, `Cache-Control: no-store`.
7. Форма показывается, только если подтверждены политика, флаг формы и готовность backend. Публичная отправка в CRM требует `EXTERNAL_WRITES_ENABLED=true`.
8. Иконки сайта созданы из официального логотипа без изменения его содержания.
9. Автоматические статические тесты: карта адресов, ссылки, SEO, обязательные медиафайлы, защита индексации. Команда: `npm run qa` (включает 10 тестов API, нужен установленный TypeScript). Добавлена собственная русская страница 404 и weekly Dependabot.

## Нельзя объявлять завершённым без проверки

- **Не запускалась полноценная сборка `npm run build`** в среде генерации: доступ к npm-реестру отсутствует.
- **Не проведён браузерный тест нового выпуска**: сервер со свежей версией ещё не развёрнут.
- Перед настоящим SEO-запуском обязательна проверка внешнего доступа с российских сетей и карта 301-редиректов старого `promsafe.ru`.
- В текущем GitHub-репозитории обнаружены отсутствующие ключевые файлы (`package.json`, `Dockerfile` в корне), поэтому автоматическая сборка из GitHub пока ненадёжна. Нужна синхронизация всего проекта, а не запуск старого workflow.
- Не подтверждены данные для заявки в CRM, актуальные цены, политика персональных данных, фото/доказательства.

## Как проверить и выпустить без удаления V8

1. Сохранить резервную копию старой папки или работать в новой папке V8.1.
2. Распаковать ZIP так, чтобы в корне были `package.json` и `Dockerfile`.
3. В терминале: `node scripts/qa.mjs`, затем `npm install`, `npm run qa`, `npm audit --omit=dev`, `npm run typecheck`, `npm run build`, `npm run dev`.
4. Проверить все ключевые страницы на desktop (1440px) и mobile (375px): главный экран, каталог, статья, форма/альтернативные контакты, калькулятор, PDF, якоря, меню.
5. Перед выкладкой убедиться, что на Railway остаётся запрет индексации и отключена отправка заявок до настройки CRM.
6. Загрузить полный исходный код в GitHub и только затем перейти к автоматической сборке Railway по GitHub. До этого допускается `railway up` из корня проекта после успешной локальной сборки.

## Переменные для staging Railway

```env
NEXT_PUBLIC_SITE_ENV=staging
NEXT_PUBLIC_SITE_URL=https://promsafe.ru
SITE_INDEXING_APPROVED=false
EXTERNAL_WRITES_ENABLED=false
NEXT_PUBLIC_LEAD_FORM_ENABLED=false
NEXT_PUBLIC_LEAD_BACKEND_READY=false
```

На основном сайте не включать индексацию до полной готовности и юридической проверки.

## Railway production service port

В этом пакете Dockerfile использует `PORT=8080` и `EXPOSE 8080`, в соответствии с существующим публичным сервисом Railway (targetPort 8080). Это предотвращает возможную ошибку 502 при развёртывании нового образа.
